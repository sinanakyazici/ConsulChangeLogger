Consul Change Logger was installed as a gateway release.

This chart does not install or own Consul, Elasticsearch, Kibana, or LDAP.
It created the Consul Change Logger Deployment, Service, and optional outbox PVC.

1. Confirm the gateway pod and Service:

   kubectl get deploy,svc,pvc -n {{ include "consul-change-logger.namespace" . }}

2. Seed runtime configuration into Consul KV using this key:

   {{ .Values.bootstrap.consulConfigKey }}

3. Route the authenticated Consul UI endpoint to this Service:

   Service: {{ include "consul-change-logger.fullname" . }}
   Port:    {{ .Values.service.port }}

   When AUTHENTICATION=true, every Consul UI and API request through this
   gateway requires a valid session. Route machine-to-machine Consul traffic
   directly to the existing Consul Service.

4. Verify health:

   kubectl port-forward svc/{{ include "consul-change-logger.fullname" . }} -n {{ include "consul-change-logger.namespace" . }} 8080:{{ .Values.service.port }}
   curl http://localhost:8080/health/live
   curl http://localhost:8080/health/ready
